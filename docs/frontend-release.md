# NP Massage Studio: приоритети и първи frontend пакет

Обхват: UX, UI, frontend сигурност и техническо SEO. Съществуващите цветови настройки, логото, снимката и оцветяването на началния екран се запазват. Резервационните полета, услугите, цените, локациите и API крайните точки се запазват. Supabase се използва само за четене. Няма миграции, промени по политики, функции или производствени записи.

## Бранд посока

Caregiver е водещата посока: грижа, внимание, спокойствие и лесен избор. Майсторството е подкрепящото качество: точни движения, ясен процес, професионално отношение. В предоставеното колело Service е мотивът на Caregiver, а Mastery е при Hero; тук използваме майсторството като професионално качество, без състезателен или агресивен Hero тон.

Говорим на „вие“, спокойно и конкретно. Показваме какво получава човекът, колко време отнема и какво следва. Пример: „Изберете масаж, локация и удобен час. Ще се свържем с вас, за да потвърдим резервацията.“ Избягваме „единственият“, „най-добрият“, недоказани лицензи, гаранции за резултат, автоматично/незабавно потвърждение и обещания за лечение.

Запазват се всички цветови токени в Tailwind и CSS. За навигацията се използва вече съществуващото светло състояние на менюто, така че текстът да се чете върху снимката. Няма нова палитра, ново лого или смяна на снимките.

## Проверки и граници

```sh
npm ci
npm run build
npm run type-check
npm run lint
npm test
```

Build използва Vite и React за предварително генериране на действителните публични страници. Прочита публикуваните блог статии с SELECT и срок 10 секунди; при недостъпна връзка използва наличните локални статии. Съществуващите резервни статии се запазват. Не изпълнява резервации, контактни форми, ваучери или cookie-consent записи.

След генерирането `out/prerender-manifest.json` съдържа адресите и canonical стойностите. Шестте вече noindex блог адреса (три теми × два езика) се отстраняват от build sitemap; техните страници остават достъпни. При грешка в генерирането build спира. `404.html` има собствено съдържание и noindex.

Тестовете проверяват действителния резервационен компонент с изолирани API заместители: грешка/повторен опит, зает час, почивен ден, успешен отговор, payload и смяна на дата. Проверяват и всички 103 генерирани документа, езиковите маршрути, промените в SEO след навигация, XSS и фокуса в менюто. Не се създават реални резервации или ваучери. Build, типове, lint и тестове са проверени локално. Cloud Browser не достига локалния preview; реална визуална проверка на променената версия в този браузър не е извършена.

Добавени са типове от прочетената Supabase схема и lockfile за повторяемо инсталиране. Типовете променят проверката на frontend кода, а не базата. Не са променяни административните записващи заявки, статусите или обработката в Edge Functions.

## Преди публикуване

Хостингът трябва да обслужва `/<route>/index.html` преди SPA fallback. Първоначалният одит показа еднакъв shell на живите адреси; генерирането само по себе си не доказва какво обслужва хостингът. В preview среда се проверяват `/`, `/en`, `/uslugi/klasicheski-masazh`, `/en/services/klasicheski-masazh`, една статия и неизвестен адрес. Нужни са реални HTTP 301 за старите адреси и HTTP 404 за неизвестните, когато хостингът ги поддържа. Не е добавена конфигурация за непотвърден доставчик на хостинг.

След публикуване се проверяват връщаният HTML, мобилен изглед, навигация и формите до стъпката преди изпращане. Реален тестов запис изисква отделно определена тестова среда или изрично разрешен тестов запис. Следят се Search Console и Google Business Profile. Първо място в Google не може да се гарантира; този пакет отстранява технически пречки и подобрява яснотата за посетителите.
